## UI

Read [`docs/DESIGN.md`](docs/DESIGN.md) before any UI work, and derive every visual decision from its principles and tokens.

**Originality rule:** the UI must be our own design. Other products may inform features and data flows; design the layout, colors, component styles, copy, and assets ourselves instead of copying theirs.

Use the names in [`docs/GLOSSARY.md`](docs/GLOSSARY.md).

| Skill                         | When to use                                       |
| ----------------------------- | ------------------------------------------------- |
| `design:design-system`        | Adding a component or token, checking consistency |
| `design:ux-copy`              | Writing buttons, error messages, empty states     |
| `design:design-critique`      | Before finalizing a design                        |
| `design:accessibility-review` | Checking contrast, keyboard use, screen readers   |
| `design:design-handoff`       | Turning a final design into implementation specs  |
| `dataviz`                     | Building Dashboard charts and statistics          |
| `artifact-design`             | Publishing an Artifact page                       |
| `ui-polish`                   | Auditing and fixing visual defects in any UI      |
| `dashboard-ui`                | Building or changing Dashboard pages              |
| `store-release`               | Releasing, testing a build, submitting, videos    |
